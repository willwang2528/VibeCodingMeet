按使用阶段分为 8 个独立模块，依次是 “分析 → 开发 → 循环 → 修 Bug → 边界测试 → 收尾 → 自评” 

---

=== 模块 1：开场分析（限时笔试） ===

```text
你是资深全栈架构师，当前正在限时2小时AI Coding笔试。  
请完整阅读本次项目README需求：  
【粘贴完整README.md全文】  

硬性规则：现阶段禁止编写任何代码、禁止实现功能，仅输出结构化分析报告，等待人工确认后，你才可以进入编码阶段。  

请按顺序完整回答以下6个维度：  
1. 需求复述：复述项目核心目标、核心功能、所有约束条件、完整交付物清单  
2. 任务分级：严格拆分【必做核心项】【加分优化项】，逐条罗列不遗漏  
3. 风险陷阱：枚举所有潜在坑点、边界bug、数据异常、权限问题、泄露风险、崩溃风险  
4. 技术栈选型：给出2套最优可落地方案，对比优劣，明确唯一主技术栈并说明理由  
5. 模块实施计划：模块划分、依赖关系、输入输出、最小可用版本  
6. 完整测试策略：覆盖正常值、空值、异常值、边界极值、复杂组合场景  

分析完毕后等待我的确认指令。
```

---

=== 模块 2：开发单个模块（实现当前模块） ===

```text
已确认你的前期分析，现在进入开发阶段，请实现开发计划里的【当前模块名称】。

1. 输出该模块完整可运行代码，配套对应单元/功能测试
2. 代码遵循工程规范、关键位置注释，禁止密钥、敏感信息硬编码
3. 完成后告诉我完整的手动测试操作步骤
4. 给出对应的git提交命令

只实现当前这一个模块，不要提前实现后续其他模块。开发完成后告知我，等待我执行测试并反馈结果。
```

---

=== 模块 3：后续模块循环（本模块测试完成，继续下一个） ===

```text
本模块测试完成，继续按开发计划实现下一个业务模块。同样输出模块代码、配套测试、手动测试步骤与git commit指令，不要超前实现其余模块。完成后等待我测试反馈。
```

---

=== 模块 4：修复 Bug（测试挂了 / 报错） ===

```text
测试出现 bug，失败案例信息：

【粘贴失败用例、报错日志、实际输出 vs 预期输出】

- 硬性约束：只修复当前这个 bug，
- 禁止改动其余已经跑通的框架、模块代码。
- 请定位根因，给出修复后的代码，
- 同时补充对应的复现测试用例。
- 修复完成给出测试验证方式，之后执行 git 提交。
```

---

=== 模块 5：修复格式 / 其他非报错问题 ===

```text
当前结果存在 XX 问题
（格式错误/密钥泄露/输出不规范），
请针对性修复，不改动主架构。
```

---

=== 模块 6：生成高攻击性测试用例（新开窗口） ===

```text
基于当前项目代码与 README 需求，

请生成10组以上高攻击性、高边界复杂度测试用例，

覆盖以下极端场景：

- 空数据
- 极值
- 脏数据
- 特殊字符
- 异常格式
- 嵌套边界
- 异常文件
- 缺失字段

输出可直接运行的测试用例  
+ 输入输出预期结果。
```

---

=== 模块 7：收尾验收（对照 README） ===

```text
核心编码已经完成，现在对照原始README.md需求做完整项目验收。

1. 逐条核对README每一条需求，输出表格：【需求条目 | 已实现/未实现 | 风险备注】；优先保证必做项全部落地，再核对加分项
2. 新建文件README-USE.md，编写项目运行说明、部署步骤、调用示例
3. 输出完整测试报告：全部测试用例、测试结果、示例输入输出样例
4. 编写已知问题列表KNOWN-ISSUES.md，写明当前系统限制与未处理边缘场景

全部交付物输出完成后，给出整体项目最终git提交指令。
```

---

=== 模块 8：自评（第三方评审） ===

```text
现在你切换为第三方代码评审专家角色，
评审上面整套项目交付产物。

请从五个维度做评审：
1. 需求完成度
2. 代码健壮性
3. 边界覆盖
4. 潜在漏洞
5. 工程规范

指出当前代码还存在哪些容易忽略的隐藏问题、遗漏边界。
输出评审意见，之后基于你的评审意见对代码做微调优化，不改动整体架构，只修补短板。
优化完成后输出更新后的代码与测试，
执行最终git提交。
```
